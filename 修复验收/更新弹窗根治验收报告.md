# 更新弹窗（Security validation failure）根治验收

日期：2026-09-18（版本定档 2026-09-19）
涉及版本：源码 v3.10.2 → **v3.10.3**
产出文件：`dist\统一工具箱.exe`（发版时会重新打包）

---

## 一、问题

用户操作「下载新版本 → 旧版自动退出 → 新版自动重启」时，偶发弹窗：

```
Security validation failure: failed to obtain executable path for parent proces!
```

特点是**文件其实已经替换完成**（再手动打开就是新版本），但自动重启那一下失败。

## 二、根因

弹窗文案来自 **PyInstaller 6.22.2 引导器**（应用中不存在该字符串）。
6.22.x 为修复 GHSA-9fxf-4qw3-ghmr 给 Windows onefile 增加了「父进程可执行文件路径校验」：
主体进程启动时会沿父进程链取 exe 路径比对，**父链上有进程已退出就弹窗**。

原先的替换脚本用 `start "" "%~2" --after-update` 拉起新版后立刻 `(goto) 2>nul & del "%~f0"`
自删除，cmd 早于新版完成校验就消失了 —— 父链断裂 → 弹窗。
v3.9.3 加的 `ping -n 8` 只是拖长窗口，19MB 的 onefile 解压慢时仍然够不着。

补充定位教训：这段字符串在引导器资源段里是 **UTF-16LE** 存储的，用 ASCII 扫描永远找不到，
这正是此前多轮排查被误导到别处的原因。## 三、修复（A 根治 + B 加固）

### A. 改用 explorer.exe 拉起新版（根治）

`explorer.exe` 是常驻 Windows Shell，永不退出 → 父进程链永远连贯。

| 项目 | 处理 |
|---|---|
| 拉起方式 | `start "" explorer.exe "%~2"` |
| 参数传递 | explorer 无法转发命令行参数，`--after-update` 改为**临时标记文件** `%TEMP%\utb_after_update.flag` |
| 载入端 | `main()` 里 `after_update = "--after-update" in sys.argv or consume_update_flag()`，读到即删，避免下次手动启动被误判 |
| DDE 丢弃兜底 | explorer 通过 DDE 把请求转给已运行实例，偶尔会丢。启动后轮询确认进程是否出现，没出现就趁 cmd 还活着直接 `start "" "%~2"` 补一次 |
| explorer 的副作用 | 被 explorer 拉起会继承它的工作目录（`C:\Windows\system32`），相对路径的图标等资源全部找不到 —— `main()` 开头 `os.chdir(exe 所在目录)` 修掉 |

### B. cmd 存活延长到约 30 秒（加固）

替换成功后 `ping -n 31` 再自删除，作为 explorer 交接缓慢时的兜底保险。

### C. 顺带挖出的第三个缺陷（原不在计划内）

替换脚本原先写的是**固定文件名** `%TEMP%\utb_apply_update.cmd`。
cmd.exe 是**边读文件边执行**的，而上一轮的脚本还活着约 30 秒；
此时再更新一次会把同一文件覆写，两个进程的执行流一起错位 ——
表现为「替换完成但新版没起来，且**没有任何提示**」。
已改为每次唯一文件名 `utb_apply_update_<pid>_<随机串>.cmd`
（最初用纳秒时间戳，实测 Windows 时钟精度不够会撞出重名，最终用 4 字节随机数）。

## 四、代码改动

- `unified/unified.py`
  - `_UPDATE_SWAPPER`（改 raw 字符串 + explorer 拉起 + 标记文件 + DDE 兜底 + 30 秒保险）
  - 新增 `_UPDATE_FLAG_NAME`、`consume_update_flag()`
  - `write_update_swapper()` 文件名唯一化
  - `main()` 增加工作目录固定、after-update 双通道识别
- `tests/test_regressions.py`：新增 5 项回归（explorer 拉起、≥25 秒保险、标记文件、
  标记读取一次即删、文件名唯一）

| Security validation 弹窗 | **0 次** |

E2E 复刻真实调用时序 `cmd /c swapper.cmd <新exe> <目标exe> <pid>`，每轮校验：

- 目标 exe 被覆盖（时间戳变化）
- 新版主窗口出现且标题正确
- 新版 cwd 为 exe 所在目录
- 更新标记已被消费
- 进程链：正常路径为 `UnifiedToolbox.exe <- explorer.exe <- svchost.exe <- services.exe <- wininit.exe`
- 全程无任何错误弹窗

分阶段打点（验证时注入，不进产品代码）：

```
正常路径   T1_WAIT_DONE | T2_COPY_OK | T3_FLAG | T4_EXPLORER_CALLED | T5_CHECKOUT LAUNCHED=1
兜底路径   T1_WAIT_DONE | T2_COPY_OK | T3_FLAG | T4_EXPLORER_CALLED | T5_CHECKOUT LAUNCHED=0 | T6_FALLBACK
```
